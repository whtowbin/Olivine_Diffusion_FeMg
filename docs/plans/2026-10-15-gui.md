# FORSTER desktop app (phase 3): design and the toolkit decision

Status (2026-10-15): design agreed with Henry; toolkit to be chosen after two
skeletons. Nothing built yet.

## Decisions (Henry, 2026-10-15)

- **Install both ways:** `pip/uv install forster[gui]`, then `forster gui`, for Python
  users; and standalone installers (macOS `.app`/`.dmg`, Windows `.exe`, Linux
  AppImage) built by CI for everyone else.
- **Platforms:** macOS, Windows and Linux, all three.
- **Toolkit:** build a skeleton in both PySide6 (Qt) and NiceGUI (web UI in a native
  window), package both on all three systems, then choose.
- **A project is a folder:** `profiles.csv`, `parameters.csv`, `diffusivities.csv` (the
  command line's own tables, so `forster fit` runs a GUI project unchanged and the
  files stay readable and diffable) plus `project.json` for GUI-only state. "Export as
  .zip" for sharing.

## What is already settled by measurement

- **Responsiveness:** fits run in a worker thread on standard CPython 3.13/3.14 with
  Numba. With the kernels releasing the GIL, a 5 ms heartbeat stayed within 5.5 ms of
  schedule during fits (it was up to 242 ms late before), so no subprocess and no
  free-threaded Python are needed (`docs/plans/2026-10-15-python-versions.md`).
- **Speed:** a fit takes about 12 ms on the default scheme, so the plot can refit after
  every drag; the initial-condition posterior takes about 0.5 s (Laplace) to 15 s
  (nested sampling), the Monte Carlo seconds: those run in the worker with progress and
  cancel.
- **Free-threaded Python is not an option for Qt today:** PySide6 has no free-threaded
  wheel.

## Shared core (built once, in the package, toolkit-independent)

`src/forster/project.py`, plain Python with no GUI imports, unit-tested:

- `Project.open(folder)` / `Project.save()`: the three CSVs through the existing
  `read_profiles`, `read_runs`, `read_diffusivities` and `summary_row`-style writers,
  plus `project.json` (format version, selected run, plot view per run, the result
  cache index).
- Runs: add, duplicate, delete, rename, "copy settings to other runs"; several runs may
  share one profile (comparing diffusion equations or starting profiles).
- Profile import: CSV or xlsx with a column mapping, Fo as % or fraction detected, a
  file holding several profiles split by its profile column.
- Validation per field, reusing the table reader's errors, so the GUI and the command
  line accept exactly the same inputs.
- Result cache: results stored under the hash of the settings that produced them, so
  a reopened project shows its results at once, and a run whose settings changed shows
  as stale rather than wrong.
- Autosave to `project.json` and a `.autosave` copy of the tables; explicit Save writes
  the tables.

Both skeletons and the final app sit on this layer, which also keeps a web front end
possible later.

## The two skeletons (throwaway, in `prototypes/`, not in the package)

Same scope in both:

1. Open a project folder (start from `forster template`'s example).
2. A run list; selecting a run shows its profile.
3. The starting profile drawn on the plot with one step position and the edge and
   core Fo as draggable lines; number fields mirror them.
4. Refit on drag release (worker thread), drawing the best fit, its 1σ band and the
   time; a Fit button for the initial-condition posterior with progress and cancel.
5. Save, close, reopen: the same state, results from the cache.
6. Packaged by GitHub Actions on macOS, Windows and Linux (PyInstaller for Qt;
   `nicegui-pack`, which wraps PyInstaller, for NiceGUI), with the build artefacts
   kept.

## How the choice is made

Measured or checked for each skeleton:

| Criterion | How |
|---|---|
| Packages and runs on all three systems | CI builds the installer; a smoke test launches it headless and fits the example |
| Installer size, cold start time | from the CI artefacts and a timed launch |
| Drag-to-redraw latency, responsiveness during a 15 s fit | timer instrumentation in the skeleton |
| Looks native and readable on each system | screenshots from each CI build |
| Code size of the GUI layer | lines outside the shared core |
| Dependencies to pin, and how often they break | count; their recent release notes |
| Unsigned-app warnings | what Gatekeeper and SmartScreen show; signing needs an Apple Developer account (decide later) |

The result goes into this file with the numbers, and Henry picks.

## The full app (after the choice)

- **Left:** the run list, with add, duplicate, delete, copy settings to other runs, and
  fit all.
- **Centre:** the plot. Measured points with the starting profile as draggable lines
  (domain ends, one or two steps, edge, core and plateau Fo); below it, the fit with
  its 1σ band, the residuals and the time distribution (`plot_time_distributions`); a
  law-comparison view (`plot_law_times`).
- **Right, tabs:**
  - Profile: data, column mapping, distance flip and offset, masking points.
  - Starting profile: number fields for the drag handles; one or two steps.
  - Conditions: T, P, and fO2 as a buffer offset or in Pa.
  - Orientation: angles to the axes, or EBSD Euler angles with the profile direction.
  - Diffusion equation: the four named choices or a custom one, with a one-line
    description of what each changes in D.
  - Uncertainties: on the starting profile (with the sampler's method, ESS and the
    share of the time spread from the starting profile), and the Monte Carlo
    (T, P, fO2, the equation; buffer-held fO2).
  - Advanced (collapsed): scheme, grid with its diagnostics, growth stages.
- **Results:** a table across runs, export of CSV, PNG and PDF, and the project folder
  itself as the record.
- **Help:** tooltips with units and the sources; errors shown next to the field.
