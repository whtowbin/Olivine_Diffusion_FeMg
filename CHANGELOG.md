# Changelog

## Unreleased

### Changed

- **Joint fits sample with a step rule; starting-profile fits model at most 10x the fitted time (2026-10-17; `docs/plans/2026-10-16-joint-calibration/`).** Calibrated on the paper's two-profile crystals against nested-sampling references, at a 5% tolerance (Henry: next to the ~0.1 log uncertainty of the diffusivity laws, a few percent of sampling error is small). The ESS did not predict the error and seeds flipped the method; the joint fit now keeps 1024 importance samples if ESS / n reaches the ideal fraction for its number of parameters, else draws 4096 and keeps them, falling back to nested sampling only below an ESS of 20: all 80 seeded decisions within 5% (worst 4.6%), no seed flips, 12 s against 116 s per fit. Single-profile fits keep their ESS threshold. With `scan_max_time_days` blank, the starting-profile fit (single and joint) now models at most 10x the nominal fit's time instead of the table's `max_time_days` (200 days gave Xenocryst_ol6, 0.23 days, a scan of 134,000 time steps); the existing tail warning says if the posterior of time reaches the end. Replay: no result changes.
- **Joint-fit defaults and the sampler's Laplace proposal (2026-10-16, Henry's go-ahead).** The starting-profile fit now refines its Laplace covariance with a second Hessian pass along the first covariance's directions (`whiten`), as the joint fit needed: the template example's sampled range moves by under 0.1% (5.682-7.623 to 5.682-7.618 days); nothing else changes in the replay. `fit_crystal`: one profile is the drift reference with no Fo offset (`fo_reference="auto"`, the profile with the most points; a run name, or None for every offset free), since the data fix only the offsets' differences; the edge position offset is off by default (`edge_offset_sd_um=0`; `forster.joint.DEFAULT_EDGE_OFFSET_SD_UM` = 2 um to turn it on), because with free steps it is barely identifiable and pushes the fit to nested sampling.
- **The desktop app imports profiles through `forster.imports` (2026-10-16).** The import dialog's guess is `forster.imports.guess` and its mapping an `ImportTemplate`: each column gets a role (oxides and elements with their name), a unit, and the guess's reason as a tooltip; the guess's notes and the mapping's problems are shown, and OK stays disabled until there are none. The import is `forster.imports.apply`, so Fo from MgO and FeO works in the app, and points whose analytical total lies outside the window (editable in the dialog, default 98.5-101.5 wt%) are kept and listed as flagged; points in exclusion columns still arrive masked, and flip, offset, the name for a file without a profile column and a run per new profile stay. "Save mapping as import template..." and "Load import template..." read and write the `forster import` templates; a file whose columns do not match is refused with the `TemplateMismatch` message. The app's own guess and importer (`profiles_from_table`, `guess_mapping`, nm distances) are gone. Core hooks, fits unchanged: `ImportResult.excluded` (the points an exclusion column leaves out) and `apply(..., name=)`.
- **Desktop app display (2026-10-16).** The Time distribution and Law comparison views follow the dark theme like the profile plot (`forster.gui.style.restyle_figure` recolours the command line's figures); the profile plot's legend sits under both panels, in rows, so it no longer covers data.

### Fixed

- **The starting-profile fit no longer fits its noise model at the prior's centre (2026-10-16).** `fit_initial_condition` fitted the first noise model at the nominal starting profile and refitted it once at the optimum. With an informative prior centred away from what the data favour (a population prior, `docs/plans/2026-10-16-population-priors`), the correlated term absorbed that misfit (4-18x larger), the search then stayed off, and the time range spread over the whole run (WHT06_ol_overgrowth1: 2.1-160 days against 1.01-1.31). The first search now scores with white noise, the noise model is fitted at that data-driven optimum, and it is refitted at each new optimum until stable (at most 4 times). A synthetic profile with a prior 2 sd off: correlated term 0.023 instead of 0.12 mol%, and the range covers the true time. The template example's sampled range moves by about 1% (5.57-7.62 to 5.68-7.62 days); grid scans are unchanged.

### Added

- **Joint fit of one crystal's profiles, from Python: `forster.fit_crystal` (2026-10-16; `docs/plans/2026-10-16-joint-fits.md`, Part 1 with Henry's answers).** Profiles of one crystal share the time, the conditions (identical T, P and fO2, else an error naming the runs) and each segment's Fo, matched by segment label; each keeps its own steps, orientation (so its own D) and noise model. The joint log likelihood at each time step is the sum over profiles of -n_i/2 log chi2_i (every profile runs its own model on one common time step). Parameters: each profile's uncertain steps (`<run>:step1_um`), the shared segment Fo (`<label>_fo`, one prior per label; runs that disagree on a shared label's nominal Fo or prior are an error), segments a profile fits on its own (`own_segments`, e.g. `<run>:b_fo`), and per profile an Fo offset for measurement drift (`<run>:fo_offset`, added to its modelled Fo; Gaussian prior sd 0.001 = 0.1 mol% by default) and an edge position offset (`<run>:edge1_offset_um`, where the true edge lies in its measured distances; sd 2 µm), either switched off with an sd of 0. The noise models are fitted per profile at the joint white-noise best fit and refitted until stable; the optimiser, Laplace importance sampling and nested fallback are `forster.sampling`'s. Each profile is first fitted alone (`fit_run`) and a warning names profiles whose 2-sigma ranges do not overlap. `CrystalFit` holds the joint best time, the central 68% and 95% of the marginal posterior of time (as `ICPosterior`), the ranges at the best starting profiles by `fit_profile`'s small-sample threshold rule (`threshold_range_days`), each shared segment's Fo and sd, each profile's steps, offsets, own best time and individual fit, the noise models, ESS and method. Growth stages and a held `edge1_fo` are errors for now; no tables, CLI or app yet. Tests (`tests/test_joint.py`): a crystal of one profile equals its starting-profile fit (same best values; range within 0.1%) and, with a fixed starting profile, `fit_profile`'s time and range; a synthetic two-profile crystal (truth 5.0 d) gives 4.65 d, 1-sigma 4.21-5.28 d, narrower than either profile alone (4.01-5.60, 4.18-5.80); a 0.15 mol% drift on one profile leaves the time within 0.3% with the Fo offsets on (fitted difference 0.139 mol%) and moves it 2% with them off; a 2 µm shift of one profile's distances is fitted as 1.83 ± 0.46 µm (steps held). A two-profile fit with both offsets takes about 1.6 s (4,800 model runs). Results of existing fits are unchanged (differential replay: 0 differences, control 0).
- **Starting-profile fit internals shared with the joint fit (2026-10-16).** `forster.sampling` gains `PriorLikelihood` (the prior and likelihood interface the optimiser and samplers use), `model_at_points`, `sample_posterior` and `at_prior_edge`, with two options the joint fit turns on and single-profile fits leave off (so their results are unchanged): `whiten`, a second finite-difference Hessian along the first Laplace covariance's directions (steps of 0.15 posterior sd instead of prior sd; on a crystal the drift offsets and the shared Fo are degenerate but for their priors, and the first pass made that direction 2.5x too narrow, ESS 64 of 1024 instead of 340), and `scaled`, which scales the nested-sampling fallback threshold by the proposal's ideal efficiency at the number of parameters (`ideal_ess_fraction`: 0.48 at 4, 0.34 at 8; the 0.25 threshold was calibrated at 2-5 parameters) and doubles the importance samples, up to 4x, until the ESS reaches 256. Not yet checked against nested-sampling references on real crystals (one synthetic case: within 0.2%).
- **Prior-conflict check in the starting-profile fit (2026-10-16).** Both fit methods report each fitted value's distance from its nominal in prior units (`ICPosterior.prior_offsets`, `ScanResult.prior_offsets`, summary.csv `scan_prior_offsets`, e.g. `a_fo=-2.25`), and warn when a Gaussian-prior value lies 2 sd or more from its nominal, short of the prior's edge (which has its own warning): the prior and the data disagree and the prior pulls the fit. Recommended by the population-priors study before any informative prior is offered.
- **Near-step check refinements (2026-10-16; `docs/plans/2026-10-15-whitening-validity/followups/`).** The near-step growth grid now runs to h = 10000 (it matched a continuous fit of h; dAIC only falls, by at most 0.26 on the paper profiles, and no warning changes on them or on the round robin profiles; WHT06_ol48 -6.63 -> -6.73). summary.csv gains `near_step_misfit_sigma_fo` (the near-step model's misfit sd at the step, better determined than h) and `near_step_points` (points within 2 diffusion lengths of a step; below about 13 a silent check is weak evidence). A note now says when the diffusion length at the best fit is shorter than the point spacing (few points resolve the front; a fit collapsing onto the step was invisible to the check).

- **Starting-profile and plateau checks (2026-10-16).** Two studies (`docs/references/noise-model-findings.md`; log in `docs/plans/noise-model-log.md`) led to three changes. On six real profiles with long plateaus, data ending where the plateau starts (about 2 diffusion lengths past the step) moved the time by -15% to +22%, and data stopping on the slope by -63% or more, while 1 diffusion length of plateau or more kept every time within 4%. `FitResult.core_end_lengths`, summary.csv `core_end_diffusion_lengths`, `forster.model.SHORT_PLATEAU_LENGTHS`. (2) The near-step warning now tells users to fit the starting profile first (`scan_method`), which cleared it on the four profiles tested (WHT06_ol48 only just, -6.6 to -5.4) and moved WHT06_ol43 by -40% (Xenocryst_ol6_prof_1 moved -52%, but its first step ended at the edge of its prior, so a sharp-step starting profile does not describe its rim), then to quote the 2-sigma range if it remains. (3) Both starting-profile fits (`fit_initial_condition` and the grid `scan_initial_conditions`) run the near-step check at their best initial condition and time (`ICPosterior.near_step_delta_aic`, `ScanResult.near_step_delta_aic`, summary.csv `scan_near_step_daic`) and warn if misfit near the step remains. `forster.model.near_step_at` and `near_step_at_best_initial` share the check. - **Near-step misfit warning (2026-10-15).** The whitening-validity study (`docs/plans/2026-10-15-whitening-validity/`) found the default noise model valid for these profiles except where the misfit is concentrated near the step, which makes the 1-sigma range too narrow (45-60% coverage, worst on dense profiles). `forster.uncertainty.near_step_check` fits a noise model whose correlated misfit may grow within about one diffusion length of a step and reports the AIC change; `fit_profile` runs it on correlated fits without growth stages (`check_near_step=True`, about 0.2 s on 300 points) and warns when the term improves AIC by more than 6 (false alarms in at most 0.2% of well-specified synthetic fits; 76-94% detection of strong cases). `FitResult.near_step_delta_aic`, `near_step_h`; summary.csv `near_step_daic`. - **Monte Carlo over temperature, pressure, fO2 and the law: `forster.rescale` (2026-10-15).** `monte_carlo(result, ConditionUncertainty(T_sd_C, P_sd_Pa, fO2_sd_log, fO2_buffer, law, between_study), posterior=None, n, seed)` draws the conditions (fO2 optionally held relative to QFM or NNO, so it follows each drawn T and P) and the law's parameters from its covariance (plus optionally the spread between laboratories), and the fit's time from its own posterior or from an initial-condition posterior (`forster.sampling`). A fixed-rim fit is rescaled, t = t_fit D_fit / D_draw (checked against refits at shifted conditions to within the time step); fits with growth stages or a changing rim are refitted per draw. Returns the draws, the 5/16/50/84/95th percentiles and the sd of log10 t from each source alone. Law only, its added spread equals the fit's linear law sigma within 5% (`tests/test_rescale.py`). Seeded, unlike the paper-era script. - **Initial-condition fitting by optimisation and sampling: `forster.sampling` (2026-10-15).** `fit_initial_condition(profile, conditions, orientation, initial, uncertainties, grid, ...)` finds the best-fit initial condition (Nelder-Mead on the uncertain step positions and Fo values, time marginalised: one model run per evaluation gives every time step) and the posterior of time over those parameters: importance sampling from a Laplace proposal (multivariate t from a finite-difference Hessian, 1024 scrambled-Sobol draws, seeded), or dynesty nested sampling when the effective sample size is below a quarter of the draws (a parameter flat across a wide prior). It returns the best values and time, the central 68% and median of the marginal posterior of time, each parameter's posterior mean and sd, its sensitivity dE[t]/dvalue, the share of the variance of time from the initial condition (law of total variance), and the evidence. On the same likelihood, Laplace and nested sampling agree with a dense grid to within 1-3% (0.3% for 4096 draws); on round robin profiles the Laplace path takes about 1,000 model runs and under a second, the nested fallback up to about 15,000 runs (`analyses/ic_sampling/`). In parameter tables, `scan_method` (auto, the default; laplace; nested; grid) and `scan_seed`; summary.csv gains `scan_sampler`, `scan_median_days`, `scan_ic_share`, `scan_sensitivity`, `scan_ess`, `scan_log_evidence`, and `<run>_scan.csv` holds the posterior of time. A table that gives `scan_points` without `scan_method` keeps the grid scan, so earlier tables and summaries refit as before. New dependency: dynesty.

### Changed

- **Fits keep a few profiles instead of one per time step, and report a 2-sigma range (2026-10-15).** The correlated method now keeps the model at the measured points for every time step (what the fit needs) and full profiles only for the start, the best fit and the ends of the 1- and 2-sigma ranges, rebuilt exactly from checkpoints at block ends (the steppers restart where they stopped): `FitResult.curve(row)`, `curve_rows`, `n_rows`. A lean fit equals one that keeps every row bit for bit (tested); `fit_profile(..., keep_curves=True)` / `fit_run(..., keep_curves=True)` keeps every row; the legacy method always does. Each fit also gives its 2-sigma range (95.45%): `time_minus2_s`, `time_plus2_s`, `indices2`, `time_range_days(..., sigmas=2)` (the law's error doubled), summary.csv `low2_days`/`high2_days`, a lighter band in `plot_fit`, and 2-sigma columns in `<run>_curves.csv`; runs are extended until the 2-sigma range is inside them. The generalised chi-squared is computed from the model at the points (`forster.uncertainty.correlated_chi2`), in Fo fits and in element fits alike, so a joint fit of Fo alone still equals `fit_profile` exactly. The round robin replay tests give both sides a longer shared time step (under each run's stability limit): all 21 still match bit for bit, the suite runs in 25 s instead of 95 s and peaks at 8.8 GB instead of 18.6 GB.
- **Round robin results moved to the private repository too (2026-10-15).** The round robin figures and results table that phase 4 had moved into `analyses/round_robin/` (41 files: model figures per sample, the results table "Round Robin_Sample Times") and 38 untracked fit tables from the root are now in the private submodule (`outputs/`, `fits/`). The round robin script writes its outputs there, and the plotting script reads `fits/`.
- **Round robin data moved to a private repository (2026-10-15).** `Diffusion Round Robin/` (other laboratories' samples, results and figures, 23 files) is now the git submodule of the private repository `whtowbin/Olivine_Diffusion_FeMg-round-robin-data`, at the same path, so scripts and tests read it as before. Tests that need it skip when it is not checked out (a public clone: 216 pass, 33 skip; with it all 285 run), through `requires_round_robin` and `require_round_robin` in `tests/conftest.py`. CI (`.github/workflows/tests.yml`: Python 3.11 and 3.13, one job without Numba, lint, ty and complexipy) checks the submodule out with a read-only deploy key (secret `ROUND_ROBIN_DEPLOY_KEY`). The files remain in this repository's earlier history.
- **Explicit schemes substep within dt; dt sets the time resolution for every scheme (2026-10-15).** A chosen final grid for `central` or `dipra` used to keep every stable step: for the packaged example (dx 0.045 um at l / dx = 240) that was 426,385 rows of 1,530 nodes, 5.2 GB in memory and 13 s, almost all of it spent storing and scoring rows 2.9 s apart for a 5-day fit. Now `choose_grid` gives the explicit schemes the same dt as the implicit one (1/400 of the fitted time for a final fit, 1/80 for a scan) or the stable step if that is longer, and `fit_profile` and the scans take ceil(ratio / 0.4) stable steps per kept row when D dt / dx^2 exceeds 0.5 (`model._explicit_substeps`; compiled and NumPy steppers). The example: 18 MB and 6.0 s, fitted time 5.137 d against 5.14 d (within the 0.25% resolution); a substepped run equals the stable run at every kept row to 1e-13 (`tests/test_grid.py`). A dt at or below the stability limit runs exactly as before, so legacy and given grids are unchanged (the differential tests pass). Unstable explicit grids are no longer refused, except with growth stages, whose start times need a stable dt; `check_grid` no longer raises for them. `forster.grid.implicit_dt` is now `resolving_dt`.
- **Kriging only for the legacy method (2026-10-13).** The default (correlated) method fits the measured points, so `fit_profile` no longer krigs the profile for it: `FitResult.interp_*` are empty and `forster fit` writes `<run>_kriged.csv` only for legacy runs. Fits are unchanged; kriging (pykrige's leave-one-out statistics, up to 0.45 s per profile) had been computed on every call, including the coarse fits that choose the grid.

- **The implicit scheme is the default (2026-10-13).** `fit_profile`, `RunDefaults`, parameter tables without a `scheme` column, scans and `choose_grid` now use `implicit` (`forster.model.DEFAULT_SCHEME`); `central` is still the default with `uncertainty = "legacy"`, so legacy results reproduce exactly, and element fits keep `central`. Refitting the existing round robin and paper tables (their own grids, dx 1 and 0.5 um) moves fitted times by a median 2.7% and up to 8.1%, 28 of 35 shorter: on those grids `central` was off by a median 2.6% (up to 8.7%) against a converged reference and `implicit` by 0.05% (up to 0.5%). Those tables' small time steps (60-600 s, set for the explicit stability limit) make implicit fits slower there (`check_grid` warns that dt is smaller than needed); leave `dx_um` and `dt_s` empty to have them chosen. The template's worked example now leaves `dx_um`, `dt_s` and `scheme` empty.
  - The explicit grid rule is corrected: error about 2.4 dx / l (was 0.65, calibrated against a biased explicit reference), so `choose_grid(scheme="central")` gives l / dx = 240 (final) and 48 (scans), and `grid_error_pct` and the coarse-grid warnings for explicit fits are about 3.7x larger than before.

- `FitResult` gains `element` ("Fe-Mg" unless an element fit) and `last_stage_s` (0 without growth stages); `plot_fit` draws element fits in their own units and greys measured points outside the model domain.
- **Small-sample correction to the 1-sigma range (2026-10-13), default.** The range is where chi-squared rises by n/(n - p) x t^2(0.8413; n - p) instead of 1 (`forster.uncertainty.interval_threshold`): 1.48 for 6 points, 1.07 for 29, 1.007 for 300. It corrects for the noise being estimated from the same points. Ranges widen by up to 22% for 6 points, 4% for 29, nothing for dense profiles; on synthetic 6-point profiles coverage rises from 49-57% to 60-66% (target 68%). Legacy is unchanged.
- **Early stopping (2026-10-13), default for the correlated method.** The model runs in blocks and stops once it is 2x past the best fit and the residuals are 4x their minimum and rising, extending if the 1-sigma range reaches the end. Fits are identical to full runs on all 35 real profiles; fitting them takes 19 s instead of 129 s. `FitResult.curves` now ends a margin past the fit rather than at `max_time_days`. Legacy always runs the full time.
- **Noise-model warning only for a profile-wide misfit (2026-10-13).** It used to fire whenever the correlation length or amplitude sat at either end of its search grid (25-35% of fits to pure white noise, with no effect on coverage). It now fires when the misfit spans the profile (L at half its length) with an amplitude of at least half the white noise; those cases covered 50-55% against 62-67% otherwise. False alarms: about 1% on pure white noise at 29 points, 8-22% on 6- and 10-point profiles.

- **New default for the uncertainty on the fitted time (2026-10-12).** The best fit and its 1-sigma range now come from the measured points rather than the kriged profile: each model curve is interpolated to the analyses, their errors are modelled as white noise plus a smooth correlated misfit (fitted by maximum likelihood, `FitResult.noise`), and the range is where that chi-squared rises by 1, interpolated between time steps (`forster/uncertainty.py`). Select with `fit_profile(..., uncertainty=...)`, `RunDefaults(uncertainty=...)` or an `uncertainty` column: "correlated" (new default) or "legacy".
  - "legacy" is the rule used from March 2026 for the round robin (`engine.Best_fit_Chi2`: reduced chi-squared of the kriged grid within 1 of its minimum, i.e. chi-squared within N - 1 for N grid points) and reproduces those results exactly. Before March 2026 (paper era) the range was where grid chi-squared reached min + sqrt(2(N-1)) (`engine.Best_fit_Chi2_old`), with time reported as (row + 1) x dt.
  - Why: the old rules counted 150-300 correlated kriged points as independent data and drew the range by rule of thumb (reduced chi-squared, which Andrae et al. 2010 show is undefined for nonlinear models); the kriging variance was also used as a standard deviation, so it had almost no effect. On synthetic profiles with a known time, the legacy range contained it 99.7% of the time when the model is exact and 62% with smooth misfit (target 68%); the new range 71% and 66%.
  - Effect on the round robin profiles: the new 1-sigma ranges are wider than the pre-March 2026 ones and narrower than legacy, and best-fit times move. Cost: 0.04-0.07 s per fit against 1.9-8.1 s for the model run; faster than the legacy grid chi-squared.
  - `FitResult` gains `uncertainty`, `fit_x_um`, `fit_fo` (the points fitted) and `noise`; `reduced_chi2` now divides by the number of points fitted.
  - Details, coverage tests and the version comparison: `docs/references/fit-uncertainty.md`, `docs/plans/2026-10-12-fit-uncertainty/`.
  - Method, worked example and validation (2026-10-13): `docs/references/likelihood-method.md`, with figures in `docs/references/figures/likelihood/` and the scripts and data in `docs/plans/2026-10-13-likelihood-validation/`. On synthetic profiles with 29 or more points and smooth misfit, coverage is 53-72% (independent errors 20-66%); the correlation length is recovered once it exceeds the point spacing. Initial-condition errors are not in the single-fit range (a 3 um step error: 21-23%); `forster.scan` covers them (65-74%).

### Fixed

- **Euler-angle tables work with NumPy 2.5 (2026-10-15).** `forster.orientation.vector_direction` called `float()` on a 1x1 matrix, which NumPy 2.5 turned from a deprecation into a TypeError, so `read_runs` failed on any row given as Euler angles (the packaged template included) for a fresh install, which gets NumPy 2.5. It now takes `.item()`; the angles are identical to the last bit on NumPy 2.3 and 2.5.4, and the full test suite passes on both. Found by the Python-version benchmark (`docs/plans/2026-10-15-python-versions.md`).
- **The importance-sampling proposal no longer fails on a nearly singular Laplace covariance (2026-10-15).** scipy's multivariate t refactorised the matrix and could reject one that had already factorised; the density is now computed from the Cholesky factor itself (`sampling._log_t_density`, equal to scipy's to 1e-12). In the validation harness's copy of the method this failed 11 of 70 cases (wide priors).
- CSV tables are read with exact float parsing (`float_precision="round_trip"`). pandas' default parser returned some values 1 ulp off, so a table written by FORSTER did not refit identically.
- Two step positions without `step_fo` (or three or more steps) are now an error naming the problem; the engine used to fail with an IndexError.

- Cross term of the diffusion equation was doubled (`diffusion_step`, found 2026-10-11). The engine solves dC/dt = D d²C/dx² + (dD/dx)(dC/dx). The cross term was built from two central differences, each spanning two grid spacings, so their product needs dividing by 4Δx²; the code divided by 2Δx². The fix changes `/ 2` to `/ 4`. It affects every Fe-Mg, Mn and Ni model where D varies along the profile, and only those (D depends on Fo). Checked against an independent flux-form solver and against DIPRA's published scheme (Girona and Costa 2013, eq. 5), which converge to the same answer as the fixed engine while the old engine does not (`tests/test_physics.py`; details in `docs/plans/2026-10-11-restructure.md`, "Engine fix").
  - Effect on fitted times: idealised single steps came out 1.3% too short for Fo 0.92 to 0.895 and 8-11% too short for Fo 0.82 to 0.885 and 0.67 to 0.745. The round robin fits move too, most of them to longer times. For Towbin and Plank (2026) the melt-vein medians move by 2-5% (1-3 weeks unchanged) and the exterior contact-overgrowth median by +28% (5.9 to 7.5 days).

- **From the 2026-10-14 review** (plan: `docs/plans/2026-10-14-review-fixes.md`):
  - No law range for a rim value that changes in time: like a growth stage, it is fixed in seconds, so the fitted time no longer scales as 1/D (measured: 0.57-0.66 of the D t shift when the rim changes over the first half of the run). Where the law range holds and where it does not: `docs/references/law-uncertainty-limits.md`.
  - A fit with a law covariance whose best fit is at time zero no longer makes `summary_row` raise; the law's error scales the high end (`widen_log10`).
  - Implicit growth stages: a stage starting a rounding error after a time step (for example one ulp) left NaN in the new zone and the solve failed; it now counts as on that step, as the last stage's start already did.
  - Explicit schemes: `fit_profile` raises if the grid is unstable for any Fo the run holds (stage zones and rim values, a fixed `rim_fo`), not only the initial condition's; a lower-Fo zone has a larger D, and the run diverged silently.
  - The coarse time estimate and explicit initial-condition scans size dt on the explicit grid's spacing (they used the implicit grid's: dt up to 5% smaller than needed).
  - `forster fit`: an error of any type in one run is reported with its type and the other runs still reach `summary.csv` (only input errors were caught, so for example an OSError lost the whole summary); KeyError messages print without quotes.
  - Profiles: rows with no distance or Fo are dropped with a warning (the paper workbook passed NaN distances into 6 of its 37 profiles, one of them a measured transect); `Marked_bad` and `Ignore` flags match in any case and with spaces; a template table warns of columns FORSTER does not use (a misspelt optional column used to be ignored silently); a malformed `inflection_c` is a ValueError; `.xls` is refused with the .csv/.xlsx message (openpyxl cannot read it).
  - Docstrings: the implicit scheme's TR-BDF2 is first order in time when D depends on Fo (D is frozen at each stage's start; measured ratio 2.05 when dt halves), second order only for a constant D.
